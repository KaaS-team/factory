# F16: TUI plan review and first-run report

## Summary

Two new terminal screens in `internal/tui`, both drawn from the KaaS design tokens in
`github.com/KaaS-team/ui/term`. The board's existing hard-coded ANSI colours now come from the same tokens.

- `factory plan-review --from-prd <file>`: the epic, its tickets grouped by wave, and for the selected
  ticket its problem, acceptance criteria, files and dependencies. `a` approves (with a y/n confirm) and
  files the plan through `factory plan --from-prd <file> --approve`. `r` asks for a revision with a note.
  A plan with problems lists them at the top and cannot be approved, the same rule as `plan --approve`.
- `factory ready [--dir]`: the first-run readiness report (F6's checks). Each check has a PASS, FAIL or
  UNKNOWN chip, its detail, and its fix or "no automatic fix". `f` applies every in-place fix after a
  y/n confirm, then shows what it fixed. `R` rechecks. It exits non-zero while a check fails, as
  `first-run --ready` does.

Closes # (cloud ticket F16; no GitHub issue)

## Plan

The brief is `docs/cloud/F16.md` on branch `briefs-2611`. What I built, by path:

- `internal/tui/theme.go`: one `theme` of Lip Gloss styles built from `term.Default`. It starts dark and
  switches when the terminal answers the background query (`tea.BackgroundColorMsg`). Status chips use
  each status's token pair, as the web chip does.
- `internal/tui/review.go`: the plan review model (`NewReview`, `PlanReview`, `Decision`). Two columns
  from 96 cells wide; below that a compact list (`W1 T1 ...`) over the detail. The detail pane scrolls
  with pgup/pgdn and says "more below" when cut.
- `internal/tui/report.go`: the first-run report model (`NewReport`, `Readiness`, `ReadyFuncs`). Checks
  run off the UI loop. Below 68 cells the detail moves under the check name. A long path keeps its end.
- `internal/tui/command.go`: `NewReviewCommand`, `NewReadyCommand` and a shared `runScreen`.
- `internal/tui/tui.go`: the board's four raw colours replaced by theme styles; it also follows the
  terminal background now.
- `cmd/factory/cmd_plan_review.go`, `cmd/factory/cmd_ready.go`: one registration file per command. They
  convert `internal/plan` and `internal/firstrun` results into the TUI's own view types, because the TUI
  may import only `internal/api` (`TestImportsOnlyAPI`). Both register with `noTool`: they are
  interactive screens, and `plan`, `approve_plan` and `first_run` already cover the actions over MCP.
- Generated or required by existing tests: `docs/cli-reference.md`, `cmd/factory/testdata/help.golden`,
  `cmd/factory/testdata/help_ee.golden`, two README command-table cells, `.ratchet.json`.
- `cmd/factory/tui_screens_test.go`: tests for the two converters.
- `docs/cloud/workflows/F16-private-modules.yml`: the CI change this needs (see Risk).
- `reports/cloud/F16/`: terminal captures, PNG and text, light and dark.

F6 (`cloud/f6`) is not on main yet, so it is merged into this branch. Merge F6 first.

## Risk and rollback

Risk: medium, because of one dependency.

- New dependency `github.com/KaaS-team/ui` (pseudo-version at `a34104b`). Maintainer: KaaS-team, the
  same org. Licence: Apache-2.0. Age: created this week. Size: the `term` package is one file with no
  dependencies beyond the `ui` module, which embeds its CSS. The brief requires it. It is consumed as a
  module, not copied, so there is one source for the tokens.
- **KaaS-team/ui is private and this repo is public.** CI has no token for it, so `go` in CI cannot
  download the module, and `go install` outside the org breaks too. Either make KaaS-team/ui public, or
  install `docs/cloud/workflows/F16-private-modules.yml` (GOPRIVATE plus a read token) into `ci.yml`
  and `release.yml`. F14 will need the same for the dashboard CSS. Locally the gate passes with
  `GOPRIVATE=github.com/KaaS-team/*`.
- Approve files tickets only through `factory plan --from-prd --approve`, which runs its own checks and
  refuses a plan with problems. The screen adds a y/n confirm in front.

Rollback: revert the PR. The two commands and the theme go together; F6 stays as merged on its own.

Decisions:

- Commands are `plan-review` and `ready`, new names rather than flags on `plan` and `first-run`,
  because those files belong to other tickets.
- `plan-review` reads `--from-prd` only. `--spec` and `--epic` need the spec parser that is unexported
  in `internal/plancmd`, which I do not own.
- Revise prints the note. There is no tracker comment to post it to for a local PRD.
- Unknown checks use the wait colours; fixes use the info colour; the selected ticket uses info.
- The screenshots are of a terminal, not a web page, so the web rules (axe, 1280x800 and 390x844) do
  not apply. I used 100x30 and 60x30 terminals instead.

Left undone:

- `plan-review --spec` and `--epic` (above).
- No vhs tape: vhs is not installed here. The pty capture script lives in the session scratchpad and is
  not committed.
- `--from-prd` problems that only `intent` finds (beyond `plan.Problems`) show after approval, when
  `plan --approve` refuses, not on the screen.
- A ui-repo candidate: the status chip and the rounded panel in `theme.go` could move to `ui/term` as
  shared helpers.
