# F15: Admin console: users, roles, policy, budgets, audit, workers

## Summary

Adds `internal/admin`, an enterprise admin console on the KaaS design system. It has five pages: users and roles (SCIM users read-only), the policy viewer and editor (`policy check` validation before save), budgets per scope with usage bars, audit search with filters and CSV or JSON lines export, and worker pools with health. Only admins get in. Every change, and every refused change, is written to the hash-chained audit log.

Closes # (ticket F15 of the cloud brief, no GitHub issue)

## Plan

The brief is `docs/cloud/F15.md` on `briefs-2611`. It builds on the W0 contracts in `ee/contract`. This branch merges the open E1, E2, E3 and F3 branches, so it builds against their real code (`ee/authz`, `ee/identity`, `ee/policy`, `ee/audit`, `ee/budget`, `internal/worker`).

What I built, all in `internal/admin` (build tag `ee`):

- `admin.go`: `Config`, `New` and the route table (`Routes`). It also holds the guard, the security headers and audit recording.
- `users.go`: SCIM users through `contract.Identity.LookupBySCIM`, so roles come from the same resolver sign-in uses. Each user shows the IdP groups that earn the role. A console-managed list (`LocalUsers`, a JSON file) holds service accounts: owners add them, change their role and disable them.
- `policy.go`: each configured layer as a summary plus a TOML editor. A save stages the text next to the target and runs `policy.CheckFile`, the same code as `factory policy check`. It then compiles every configured layer with the new file in place, so narrowing the org file cannot leave a team file widening. Only a clean file is renamed over the old one. Signed layers are read-only.
- `budgets.go`: the effective limits from `policy.Resolve`, with usage from `contract.Budget.Remaining`. Each usage bar is a native `<progress>` element, coloured by status. An edit changes the limit in the narrowest layer that sets it and goes through the same check as the policy editor.
- `auditlog.go`: filters for actor, action, outcome and date range, newest first, plus the chain status from `Audit.Verify`. Export gives CSV or JSON lines with the hashes, and the export itself is recorded first. CSV cells are guarded against formula injection.
- `workers.go`: a `Workers` port (`List`, `Drain`, `TTL`), a stat per pool, a health chip per worker (healthy, late after one missed TTL, lost after three, draining) and a drain action.
- `templates/*.tmpl` and `static/admin.css`: pages built from `ui.Partials` (shell, nav, chip, table, empty, form, stat, attention) and `--ui-*` tokens only. No inline styles, no scripts, and a CSP of `default-src 'none'; style-src 'self'`.

### Decisions

- **Who is an admin.** Every route needs `settings.write` (owner and admin) on top of its own action. A member, viewer or bot gets 403 on every route, reads included, even though members hold `policy.read` and `budget.read`. User changes need `admin.users`, which only owners hold, so admins see the users page with no edit controls.
- **Audit first.** A change writes its allow event before it is applied. If the apply fails, an error event follows. If the audit write fails, nothing changes. A refused change (by authz or by the policy check) is a deny event carrying the reason code.
- **SCIM users are read-only.** The IdP owns them. A role or status POST for a SCIM id returns 404 and records nothing. Owners cannot disable themselves.
- **Browser auth.** The credential is the bearer header or the `factory_token` cookie, verified by `contract.Identity`. A cookie POST must be same-origin (`Sec-Fetch-Site` or `Origin`); cross-site posts get 403 `admin.cross_site`.
- **Budget edits re-encode the layer file** with the TOML encoder, so comments in that file are lost. `TestPolicyFileSurvivesReencode` pins that every key of the example policy comes back the same, and that `[]` stays different from unset.

## Risk and rollback

The risk is medium. The new package is reached by nothing yet, so it cannot change running behaviour. The visible risks are in the merge: `go.mod` gains `github.com/KaaS-team/ui`, a private module. CI needs `GOPRIVATE=github.com/KaaS-team/*` and a token that can read that repo, or `go mod download` fails. To roll back, revert the F15 commits. The dependency merges go away when E1, E2, E3 and F3 land on their own.

### Left undone

- **Not mounted yet.** No command serves the console. A host mounts `admin.New(cfg).Handler()` at `/`. `internal/serve` belongs to E1 and has no production identity wiring yet, so I did not add a `factory admin` command against a fake. That needs a wiring ticket.
- **Worker listing.** `broker.Leaser` has `Drain` and `TTL` but no way to list workers, and `internal/dispatch/broker` is F3's. The console takes a `Workers` port. A `Leaser.Workers()` snapshot (id, pool, labels, caps, draining, last seen, held job) would let the plane satisfy it directly.
- **Console users are not used for sign-in yet.** `LocalUser.Principal` returns the contract principal, but `ee/identity.Directory` (E1) does not consult the console list. API tokens for these service accounts are also not minted here.
- **Sign-in flow.** The console reads a bearer header or the `factory_token` cookie. Setting that cookie after an OIDC or SAML sign-in belongs to the SSO session work.
- **Candidates for the ui repo:**
  - The usage bar (`progress.admin-bar`), the inline row form, the definition grid and the code editor textarea.
  - The `.ui-table-wrap { position: relative }` fix for hidden labels in scrolling tables.
