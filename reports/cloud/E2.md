# E2: kaas-policy.toml policy engine

## What I built

- `ee/policy/kaas.go`: `Compiler` (implements `contract.PolicyCompiler`), `Effective` (implements `contract.Policy`, plus `Explain`), schema `Validate`, strict `Decode` (unknown keys fail), `Load` with optional per-layer signature check through `packs.ReadFileSigned` (the scheme `ee/policy/signed.go` uses).
- `ee/policy/run.go`: layer paths (`--org`, `--team`, repo `.factory/kaas-policy.toml`, env `FACTORY_POLICY_ORG`, `FACTORY_POLICY_TEAM`, `FACTORY_POLICY_KEY`), `CheckFile`, `Explain`, `Resolve`.
- `internal/policygate`: the one place core asks the policy. No policy set means allow, so the default build is unchanged.
- Enforcement at the decision points (small, additive):
  - dispatch: `cmd/factory/control.go` wraps every dispatcher in `policygate.Wrap`; it refuses a harness or named model not on the list.
  - MCP config: `internal/dispatch/local/preset.go` `ClaudeArgv` refuses an unlisted MCP server.
  - mergeq: `internal/mergeq/run.go` `Runner.policy` ejects a PR whose risk class is not in `auto_merge_risk`; `Entry.Risk` added.
  - Every refusal wraps `policygate.ErrDenied` and carries a contract reason code (`policy.not_allowlisted`). The message names the check kind, not the model or host.
- CLI: `factory policy check [path]`, `factory policy explain <value> [--check ...]` (`cmd/factory/cmd_policy.go`, `cmd_policy_kaas.go`). The old `factory policy <action> --rules` still works.
- MCP: tool `policy` (`internal/mcp/tool_policy.go`), action `check` or `explain`. The `noTool` gap on the command is removed.
- Startup wiring (ee build): when an org file or a repo file is present, the policy loads and is set. A file that fails to load stops the command, so a broken file never means no policy.

## Decisions

- Harness name: Claude presets (`claude`, `claude-plan`) map to harness `claude-code`; any other preset is its own name. Matches the example file.
- A queued PR with no risk class is treated as outside the policy and ejected, but only when a policy is set (default deny). `Entry.Risk` is not filled by `CoreQueue` yet, so with a policy set every auto-merge is refused until F8 or F10 sets it. Ejection tells the PR a human review is needed.
- A brief with no model uses the stage default, which dispatch cannot see, so only a named model is checked.
- Only org and team files are signature-checked when `FACTORY_POLICY_KEY` is set. The repo file is never signed, because the signature protects the org file from the repo.
- Layer files come from env and flags, not `internal/config`, to stay in the paths I own.
- `.ratchet.json` raised by hand: +36 lines, +1 deadcode (`policygate.Configure`, called only in the ee build), reason appended.
- Edits outside my paths, all additive: `.ratchet.json`, `internal/mcp/mcp_test.go` (new tool in the name and args tables), `cmd/factory/testdata/help_ee.golden`, `cmd/factory/control.go` (one wrap), `internal/mergeq/plan.go` (`Risk` field). No CHANGELOG line: it has no unreleased section.
