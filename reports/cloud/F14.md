# F14: Fleet web app: board, attention inbox and run timeline

Status: done, with the open items listed under "Left undone".

## Summary

`factory dashboard` now serves a fleet app built on the KaaS ui partials. It has a board of runs by
state and wave, the attention inbox, and a run page with a live timeline and log. From the run page
you can retry, cancel or steer a run. Every route asks a `contract.Authorizer` before it reads or
writes. The old bare HTML dashboard is gone.

## Built

- `internal/web` (new):
  - `web.go`: `Handler(ctl, Options)`, the route table, sign-in by bearer token or cookie, CSRF
    (double-submit cookie plus Origin check), CSP and security headers, and the error screen.
  - `board.go`: five columns (Ready, Running, Needs you, Merge queue, Done) from one phase table,
    a wave number per run from `plan.Waves`, the merge queue in queue order, and summary stats.
  - `inbox.go`: the attention inbox from `attention.Lister`, and resolve (approve, reject, retry,
    dismiss) through the store's `Resolve` when the Control offers it.
  - `run.go`: the run page (history timeline, event log, steer form, retry and cancel), the per-run
    and board SSE streams, and the scrubber that keeps operator detail out of customer views.
  - `signin.go`: the token sign-in form, a safe `next` redirect, and sign-out.
  - `templates/*.tmpl`: app frame, board, inbox, run, sign-in and error. They use the ui partials
    `head`, `chip`, `stat`, `empty`, `attention`, `timeline`, `log`, `form` and `button`.
  - `static/app.css`: layout on `--ui-*` tokens only. `static/app.js`: live updates over SSE.
  - `web_test.go`: 16 tests (list below).
- `internal/dashboard`: `NewCommand` serves `web.Handler` behind the host guard. A new flag,
  `--allow-actions`, turns on writes for the local user. The old templates, goldens and handlers
  are removed.
- Generated files the gate regenerates from the command tree: `docs/cli-reference.md`,
  `cmd/factory/testdata/help.golden`, `cmd/factory/testdata/help_ee.golden`. Each diff covers only
  the `dashboard` short text and the new flag.
- `go.mod`, `go.sum`: `github.com/KaaS-team/ui`.
- `.ratchet.json`: baseline raised, reason appended.
- `CHANGELOG.md`: one line.
- Branch merges: `origin/cloud/f7`, `origin/cloud/f8` and `origin/cloud/f12` are not on main yet, so
  they are merged in. I resolved three conflicts between F7 and F8 (`internal/mcp/mcp_test.go` tool
  list, the `README.md` command row and `.ratchet.json`) by keeping both sides.

## Routes and authz

| Route | Action checked | Signed out | Denied |
|---|---|---|---|
| `GET /` | `run.read` per run repo | 303 to /signin | runs filtered out |
| `GET /attention` | `run.read` per item | 303 | items filtered out |
| `POST /attention/{item}` | `approve` (approve, reject, dismiss), `run.retry` (retry) | 401 | 403; 404 when the item is hidden |
| `GET /runs/{id}` | `run.read` | 303 | 404, never 403 |
| `GET /runs/{id}/events` | `run.read` | 401 | 404 |
| `POST /runs/{id}/retry`, `/cancel`, `/steer` | `run.retry`, `run.cancel`, `run.steer` | 401 | 403, or 404 when the run is hidden |
| `GET /events` | `run.read` per event | 401 | events filtered out |
| `GET /ticket/{id}` | redirects to `/runs/{id}` | 303 | |
| `GET /_ui/`, `/static/`, `/signin`, `POST /signin`, `/signout` | public | | |

`TestEveryRouteWithAuthz` walks `routes()`. Each route has a case for a signed-out caller, a
denied caller and an allowed caller. A route added without a case fails the test.

## Decisions

- **Local mode.** With no `Identity`, every request acts as one local user, and the server listens
  on loopback behind the host guard, as before. It is read-only unless `--allow-actions` is passed.
  The old dashboard was read-only, and a browser on loopback can be reached by CSRF. Actions also
  need a CSRF token and a matching Origin.
- **Enterprise mode.** `Options{Identity, Authorizer, Org}`. `Handler` panics when an Identity
  comes without an Authorizer or an Org, so authz cannot be left off by accident. The resource org
  is the factory's org, never the caller's.
- **No new authz resolver.** Decisions come only from `contract.Authorizer`. The test authorizer
  reads `contract.Grants`.
- **A hidden run or item answers 404, never 403.** This follows the house API rule.
- **Waves come from `plan.Waves`.** The TUI has its own unexported `waves` (F16's path). I did not
  copy it. Blockers that are off the board count as done. A cycle puts every run in wave 1.
- **Attention write side.** Resolve uses the store's `Resolve(id, action, by)` through a type
  assertion on the Control, the same way `attention.Lister` is reached. Approve, reject and dismiss
  need `approve`, which only a user may take. Retry needs `run.retry`.
- **Customer view.** Token counts, spend, budget caps, dispatcher names, session ids and budget
  events show only with `--operator`. Event data is cut to an allow-list of keys and passed through
  `redact.Strict`.
- **Live updates.** The run page appends timeline and log entries from SSE. The board and inbox
  fetch their own URL again and swap the region in place. Every page works without script.
- **CSP** is `default-src 'self'`: no inline script, style or handler. A test checks every page.
- **No new ui components were needed** beyond app layout. Candidates for the ui repo: `.fw-board`
  (kanban columns), `.fw-skip` (skip link) and a nav count inside a `NavItem`.

## Left undone

- **CI cannot fetch the private ui module.** CI fails at `vet` with `github.com/KaaS-team/ui...:
  invalid version: git ls-remote ... could not read Username for 'https://github.com'`. The module
  is private, and the runner fetches it anonymously. The fix is a workflow step, which cloud sessions
  cannot push. It is in `docs/cloud/workflows/F14-private-ui-module.yml` and needs one secret,
  `KAAS_UI_READ_TOKEN`, with read access to KaaS-team/ui. The PR stays red until it is installed.
- **ee wiring of `factory dashboard`.** `web.Options` takes an Identity, an Authorizer and an Org,
  but there is no `ee/authz` implementation on main yet (E1). Passing them from the command belongs
  to an `//go:build ee` file in `cmd/factory`, outside my paths. Until then the command runs in
  local mode.
- **Logs are the event stream.** The log panel shows the run's events as lines. The Control has no
  method for raw agent session output. `internal/logs` reads routine logs through its own Resolver,
  outside `api.Control`. Adding that read is a contract change.
- **The axe and screenshot run is not in the gate.** It needs Node, Playwright and axe-core, and
  the Go gate has none of them. The script is in the session scratchpad, not the repo. If the
  orchestrator wants it in CI, it could become a `docs/cloud/workflows/F14-axe.yml` job.
- **Rebase.** `origin/main` had not moved since this branch started (`34312ec`), so there was
  nothing to rebase.
- **Sign-out on phones.** The ui collapses `.ui-nav-foot` below 720px. `app.css` shows the
  sign-out button again there. Look at the enterprise-mode phone nav once ee wiring lands.

## New dependency

`github.com/KaaS-team/ui` at `v0.0.0-20261126201939-a34104b922e4`. It is the KaaS design system
that the brief requires. Maintainer: KaaS-team. Licence: Apache-2.0. The module is about 0.5 MB of
CSS and templates and has no Go dependencies of its own. It has no tagged release yet, so this is
a pseudo-version of main. The repo is private, so `proxy.golang.org` cannot serve it and Go fetches
it from GitHub with credentials. CI needs the step in `docs/cloud/workflows/F14-private-ui-module.yml`.
